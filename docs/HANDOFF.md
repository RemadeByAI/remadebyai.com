## Site layout (directory structure, built 2026-11-21)

The site is a static app directory generated from one data file. **Add or change apps in `projects.json`, then run `node build.js`** (Node 18+, no packages) and commit everything it changed. The build checks the data first and refuses to build if an entry is wrong (missing field, bad date, duplicate slug, missing screenshot file).

What `build.js` writes (never edit these by hand; they are rebuilt from scratch each run):
- `apps/<slug>/index.html`: one page per app (facts table, download/site buttons, screenshots, "How it was built with AI", "Our review", more in the same category, schema.org SoftwareApplication data).
- `categories/index.html` and `categories/<slug>/index.html`: category list and one page per category (A to Z).
- `new/index.html`: every app, newest first.
- `apps/index.html` (**All apps**, since 2026-11-22): the full A to Z list with search and filters (directory.js). It used to be on the home page.
- `about/index.html` and `list/index.html`: the About and List your app pages, wrapped from the hand-edited `partials/about.html` and `partials/list.html` (the contact form lives in `partials/list.html`; contact.js loads only there).
- `sitemap.xml` and `robots.txt`.
- `search.json`: the header search index.
- `index.html`: only the regions between `<!-- build:NAME -->` and `<!-- /build:NAME -->` markers (asset links, header, stats line, featured block, one row of new arrivals, category tiles, app count, footer). Everything else (hero, the two link cards at the bottom, the redirect script) is hand-edited.

**Home page (decluttered 2026-11-22, owner felt it was overcrowded):** hero (shorter, with Browse all apps / Categories buttons and an "N apps in N categories" line), the rotating featured app, ONE row of new arrivals (as many as fit the width, 3 stacked on phones; descriptions clipped to 2 lines), category tiles (name, count, first 3 apps), and two link cards (All apps, List your app). Footer on every page links All apps, New arrivals, Categories, About, List your app. Home page height went from 6,762px to 2,432px at 1440 wide (18,064 to 4,570 on a phone). Old links keep working: a script in index.html sends `/?q=...` and other filter links to `/apps/?...`, and `/#directory`, `/#about`, `/#list` to their new pages. Previews: /mnt/project-files/previews/declutter/.

Other files:
- `site.js` (every page, added 2026-11-22): the **header search box** (gets the text cursor on page load on computers with a mouse; not on phones/tablets, not when the URL has a #hash, no scrolling) and **click counting**. The box suggests up to 7 apps as you type, from `search.json` (written by the build: name, what it replaces, category, maker, platforms, price, licence, description), ranked name > replaces > maker/category > the rest. Enter or "See all" opens the All apps list filtered (`/apps/?q=...`); without JavaScript the box is a plain GET form to `/apps/` that does the same. Links with `data-track` (Download, Visit site, Source code, featured button) send an anonymous beacon to the clicks Worker when `ANALYTICS.clicksEndpoint` is set.
- `directory.js`: search and filters on the All apps page (`/apps/`): group buttons (All / EmuKey apps / Open source) and dropdowns for category, platform, price (Free, Freemium, Paid) and licence (MIT, Apache-2.0, GPL-3.0, AGPL-3.0, Unlicense, Closed source). Each `select[data-filter=NAME]` matches the card's `data-NAME` list, so a new filter only needs build.js changes. Price and licence values are derived from the free-text `price`/`license` fields by `priceTags()`/`licenceTags()` in build.js (SuperCmd counts as Free and Paid; dual licences count under both; no licence and no source = Closed source). The current filters are kept in the address bar, so links like `/apps/?q=email`, `/apps/?category=productivity`, `/apps/?platform=Linux&price=Free` or `/apps/?group=open&licence=MIT` open pre-filtered (old `/?...` links redirect there).
- **Analytics** (`ANALYTICS` in build.js): `cloudflareToken` adds the Cloudflare Web Analytics beacon to every page (visitors, page views, referrers, countries, devices; no cookies, no banner needed; works on GitHub Pages because it's a JS beacon). `clicksEndpoint` turns on outbound click counting via the Worker in `clicks-worker/` (Workers KV; stats page at `/stats?key=STATS_KEY`). The owner keeps **one Cloudflare account per app**, so both belong in a RemadeByAI Cloudflare account, not the InCloseMail or DesktopWiki ones. (The contact form Worker `remadebyai-forms` currently runs in the InCloseMail account.)
- `partials/art-<name>.html`: artwork for the featured block, chosen by the featured entry's `featureArt` (`inbox` is the InCloseMail mock, `wiki` the DesktopWiki mock).
- `styles.css`: all styles. Layout scales to wide screens (added 2026-11-21): `.wrap` grows to 150rem, the root font size steps up at 1800/2300/3000px wide, and `.cards` is an auto-fill grid (17rem minimum), so 1080p shows 6 columns, 1440p 7 and 4K 8. Dark theme, green accent `#c2ff94`. Tile colours: `wiki`, `capture`, `code`, `glance`, `voice`, `bar`, or empty for green.
- **Screenshot viewer (`site.js`, 2026-11-22):** clicking a screenshot on an app page opens it large in a dialog with a round X button (top right). Esc, the X, or a click anywhere outside the picture closes it; left/right arrow keys, the on-screen arrows or a phone swipe move between screenshots; focus returns to the thumbnail. Ctrl/middle-click still opens the image file in a new tab.
- **Light/dark mode (2026-11-22):** a button in the header ("☀ Light mode" / "☾ Dark mode", icon only on phones) matching the toggle on InCloseMail and DesktopWiki. Dark is the default; the choice is saved in localStorage `theme` (same key as those sites). Links that already set `target` are left alone. Click counting still works (checked).

### projects.json fields

Required: `name`, `group` (`emukey`, `open`, or `indie` for closed-source apps by others), `owner`, `alternative` ("Alternative to X"), `description` (one or two sentences), `category`, `url`, `added` (YYYY-MM-DD, drives New arrivals).

Optional: `slug` (default from name), `icon`, `tile`, `linkText`, `download` (direct download or releases page; adds a Download button), `source` (repo link), `platforms` (any of Windows, macOS, Linux, Web, iOS, Android), `license` (e.g. MIT, GPL-3.0, Proprietary), `price` (Free, Freemium, Paid), `maker` (who makes it), `longDescription` (paragraphs separated by a blank line), `screenshots` (list of `{ "src": "/assets/apps/<slug>/1.png", "alt": "...", "caption": "..." }`), `builtWithAI` (how AI was used, with the source of that claim), `review` (`{ "date", "body", "verdict", "version", "author" }`), `keywords` (extra search words that are never shown, e.g. `["wow", "world of warcraft"]` on World of ClaudeCraft; they go into search.json as `k`, ranked just below the name, and into the All apps filter).

Featured: `featured: true`, plus `tagline`, `featureText`, `featureLinkText`, `featureArt`. More than one entry can be featured (since 2026-11-22: InCloseMail and DesktopWiki). The build renders all of them in the featured block, and a small inline script shows one at random on each page load. Without JavaScript the first featured entry in `projects.json` shows.

Only state facts that have been checked. Leave unknown fields out; the page hides them.

## Build gotcha (fixed 2026-11-22)

- `replaceRegion()` in build.js used a replacement string, so a `$1` inside app text (SuperCmd's "$19.99") was read as a regex group and wrote a stray `<!-- build:cards -->` into the page. It now uses a replacer function. Use functions, not strings, for any new `.replace()` that inserts app text.

## Cache busting

- `build.js` adds a content hash to the `styles.css`, `site.js`, `directory.js` and `contact.js` links on every page (`?v=<hash>`), so there is nothing to bump by hand. Just rebuild after changing either file.
