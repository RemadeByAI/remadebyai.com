## Site layout (directory structure, built 2026-11-21)

The site is a static app directory generated from one data file. **Add or change apps in `projects.json`, then run `node build.js`** (Node 18+, no packages) and commit everything it changed. The build checks the data first and refuses to build if an entry is wrong (missing field, bad date, duplicate slug, missing screenshot file).

What `build.js` writes (never edit these by hand; they are rebuilt from scratch each run):
- `apps/<slug>/index.html`: one page per app (facts table, download/site buttons, screenshots, "How it was built with AI", "Our review", more in the same category, schema.org SoftwareApplication data).
- `categories/index.html` and `categories/<slug>/index.html`: category list and one page per category (A to Z).
- `new/index.html`: every app, newest first.
- `apps/index.html` (**All apps**, since 2026-11-22): the full A to Z list with search and filters (directory.js). It used to be on the home page.
- `about/index.html` and `list/index.html`: the About and List your app pages, wrapped from the hand-edited `partials/about.html` and `partials/list.html` (the contact form lives in `partials/list.html`; contact.js loads only there).
- `badge/index.html` (2026-11-22): the "Listed on RemadeByAI" badge page, with an app picker (`?app=<slug>` preselects) and copy-paste Markdown (dark, light) and an HTML `<picture>` snippet that follows GitHub light/dark mode. Each app page ends with a small collapsed "Made X? Add a badge to your README" box with that app's snippets (`badgeBox()` in build.js). The badge images are hand-made SVGs in `assets/badge/listed-dark.svg` and `listed-light.svg` (172x28); keep those URLs stable, since makers' READMEs point at them. Copy buttons are handled in site.js. Makers are never contacted about it.
- `sitemap.xml` and `robots.txt`.
- `search.json`: the header search index.
- `index.html`: only the regions between `<!-- build:NAME -->` and `<!-- /build:NAME -->` markers (asset links, header, stats line, featured block, one row of new arrivals, category tiles, app count, footer). Everything else (hero, the two link cards at the bottom, the redirect script) is hand-edited.

**Home page (decluttered 2026-11-22, owner felt it was overcrowded):** hero (shorter, with Browse all apps / Categories buttons and an "N apps in N categories" line), the rotating featured app, ONE row of new arrivals (as many as fit the width, 3 stacked on phones; descriptions clipped to 2 lines), category tiles (name, count, first 3 apps), and two link cards (All apps, List your app). Footer on every page links All apps, New arrivals, Categories, About, List your app. Home page height went from 6,762px to 2,432px at 1440 wide (18,064 to 4,570 on a phone). Old links keep working: a script in index.html sends `/?q=...` and other filter links to `/apps/?...`, and `/#directory`, `/#about`, `/#list` to their new pages. Previews: /mnt/project-files/previews/declutter/.

The box suggests up to 7 apps as you type, from `search.json` (written by the build: name, what it replaces, category, maker, platforms, price, licence, description), ranked name > replaces > maker/category > the rest. ### projects.json fields

Required: `name`, `group` (`emukey`, `open`, or `indie` for closed-source apps by others), `owner`, `alternative` ("Alternative to X"), `description` (one or two sentences), `category`, `url`, `added` (YYYY-MM-DD, drives New arrivals).

Optional: `slug` (default from name), `icon`, `tile`, `linkText`, `download` (direct download or releases page; adds a Download button), `source` (repo link), `platforms` (any of Windows, macOS, Linux, Web, iOS, Android), `license` (e.g. MIT, GPL-3.0, Proprietary), `price` (Free, Freemium, Paid), `maker` (who makes it), `longDescription` (paragraphs separated by a blank line), `screenshots` (list of `{ "src": "/assets/apps/<slug>/1.png", "alt": "...", "caption": "..." }`), `builtWithAI` (how AI was used, with the source of that claim), `review` (`{ "date", "body", "verdict", "version", "author" }`), `whatPeopleSay` (2026-11-23: "What people say" section above Our review, compiled from public discussion: `{ "checked": "YYYY-MM-DD", "summary", "praise": [], "complaints": [], "sources": [{ "title", "site", "url", "date", "quote" (short, verbatim, max 40 words, re-check before going live), "who", "points" }] }`; our own words plus short attributed quotes and links, never whole reviews; say so when coverage is thin), `keywords` (extra search words that are never shown, e.g. `["wow", "world of warcraft"]` on World of ClaudeCraft; they go into search.json as `k`, ranked just below the name, and into the All apps filter).

Featured: `featured: true`, plus `tagline`, `featureText`, `featureLinkText`, `featureArt`. More than one entry can be featured (since 2026-11-22: InCloseMail and DesktopWiki). The build renders all of them in the featured block, and a small inline script shows one at random on each page load. Without JavaScript the first featured entry in `projects.json` shows.

Only state facts that have been checked. Leave unknown fields out; the page hides them.

## Search engines and speed (2026-11-23)

All of this is written by build.js; keep it when editing templates.
- **Titles and descriptions:** app titles are "Name: Alternative to X | RemadeByAI", dropping "| RemadeByAI" when over 65 characters. Meta descriptions are clipped at a word to about 155 characters (`clip()`). Category pages get their own description (count, three newest names, what they replace; `categoryDescription()`).
- **Link previews:** every page has Open Graph and Twitter tags with image alt text. App pages use their first local screenshot as the preview picture (size read from the file); other pages use `assets/og-image.png`.
- **Structured data (JSON-LD):** app pages have SoftwareApplication (Google app type mapped from our category in `APP_CATEGORY`, platforms, licence, download link, screenshots, a free Offer only when the price is plainly Free or an exact $ price) plus BreadcrumbList. Category pages have ItemList plus BreadcrumbList. The home page has Organization (EmuKey LLC) and WebSite with the site search (`<!-- build:jsonld -->` region). Review markup is added only for our own `review` (never for EmuKey's own apps), and never from the "What people say" quotes, which are third-party. No star ratings.
- **sitemap.xml** has `lastmod` per page: the newest of `added`, `review.date` and `whatPeopleSay.checked` (category and list pages take the newest of their apps). **robots.txt** keeps /docs/, /clicks-worker/, /forms-worker/ and /partials/ out of search. **404.html** (noindex) shows the newest apps; GitHub Pages serves it for any missing address.
- **Headings:** one h1 per page; on list pages (categories, new, all apps, 404) card names are h2, elsewhere h3 (`card(app, level)`; style is `.card .card-title`).
- **Screenshots:** the grid shows a thumbnail at most 960 px wide (`assets/apps/<slug>/thumb/`), linked to the full picture that the viewer opens. Images carry width/height so pages don't jump while loading. **After adding screenshots, run `python3 tools/make-thumbs.py` (needs Pillow), then `node build.js`.** Without a thumbnail the page just uses the full image.
- **search.json** now loads only when someone uses the search box (click, focus by hand or typing), not on every page load.

## Build gotcha (fixed 2026-11-22)

- `replaceRegion()` in build.js used a replacement string, so a `$1` inside app text (SuperCmd's "$19.99") was read as a regex group and wrote a stray `<!-- build:cards -->` into the page. It now uses a replacer function. Use functions, not strings, for any new `.replace()` that inserts app text.

## Cache busting

- `build.js` adds a content hash to the `styles.css`, `site.js`, `directory.js` and `contact.js` links on every page (`?v=<hash>`), so there is nothing to bump by hand. Just rebuild after changing either file.
